  $ grep -cin 'zcode\|codegeex' scanner/internal/scanner/agents/dsl_mode.go
  0                       <-- ZCode/CodeGeeX are NOT flag-gated

WHY THIS IS CORRECT: `flagGatedAgents` is the set whose implementation the
ONYX_SCANNER_DSL_ENABLED flag MOVES between the native detector and the DSL shadow —
exactly one pair (claude-code, codex). It is NOT "the list of DSL agents". ZCode/CodeGeeX
ship as always-on DSL agents; putting them in flagGatedAgents would (a) drop their DSL
detector whenever the flag is OFF (SelectDSLDetectorsForMode filters flag-gated names,
dsl_mode.go:159-168), making the runtime vanish, and (b) is unnecessary because they have
no competing native implementation to gate against. Absence here is the intended wiring.

WHY THIS IS CORRECT — the fixture set is a CURATED INSTALL-LANE SUBSET, not an exhaustive
mirror of the scanner's detectable-agent registry:
  * These fixtures model agents with a real VM install/login/invoke/hooks lane the daemon
    e2e DRIVES end-to-end (npm_package, version_command, login_spec, hooks_installed(),
    config_model(); see codex.py). fixtures.py writes MCP/skill entries into each agent's
    OWN config so DSL-detection assertions have something distinctive to find.
  * Many agents the scanner DOES detect have NO daemon fixture either — proving the set is
    representative, not complete:
       Kiro       (scanner/internal/scanner/agents/kiro_test.go)
       Cline      (embedded_dsl_cline_test.go)
       LMStudio   (lm_studio.go)          AnythingLLM (anythingllm.go)   Qoder (native)
    None of these five has a daemon/e2e fixture, yet all are scanner-detected.
  * No completeness contract exists: daemon/e2e/tests/unit/test_agents.py imports exactly
    the five classes above and tests each with its OWN explicit functions — there is NO
    "all detectable agents" parametrize / registry-completeness assertion that a new agent
    is required to join. (conftest.py enumerates only the machine matrix, not agents.)

  ZCode/CodeGeeX are DSL-DISCOVERY-ONLY agents with no daemon install-lane in this PR's
  scope. A daemon fixture would additionally require the Zhipu ZCode / CodeGeeX CLIs to be
  installable on the CI cloud-VM matrix (aws:linux:amd64 default) — out of scope here. Their
  REAL install + scan is proven on the provisioned lab host instead (rows S1 / C1 / C2:
  ZCode 3.11.2 + CodeGeeX 2.27.6 installed, scanned, byte-faithful payload -> DB row), and
  the runtime hooks lane is proven live (C7: real /guard/evaluate/zcode request).
